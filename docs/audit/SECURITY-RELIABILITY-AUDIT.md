# Ternux V3 security and reliability audit

**Baseline commit:** `f04b7261ef9ba2dba2c38fd987f760e80583f2d2`\
**Status:** independent baseline findings recorded; full component-by-component review remains in progress.\
**Scope boundary:** source/workflow and fixture review plus read-only inspection of the installed v2.0.1 host. No live guest, Android setting, service, or project installation was changed.

## Findings

| ID | Severity | Finding and evidence | State / required gate |
|---|---|---|---|
| SEC-01 | High (corrected locally) | Baseline had 64 third-party GitHub Actions references using version tags and 0 full SHAs. All 64 are now pinned to 10 resolved action commits with readable release labels. Global workflow permissions are generally `contents: read`; `contents: write` is scoped to artifact publication/repository-state jobs, while Pages jobs use `pages: write` and `id-token: write`. Secrets are limited to the APT signing job and the SKB dispatch step. | Corrected locally. `tests/workflow_action_pin_policy.py` checks all current refs and is wired into Validate CI. Release tags were resolved to exact commits and official commit pages inspected. Exact-head CI for the changed workflow and follow-up workflow permission/token review remain pending. |
| SEC-02 | High | Direct-pipe `uninstall.sh` fallback fetches `lib/core.sh`, `lib/desktop.sh`, and `lib/uninstall.sh` from `raw.githubusercontent.com/.../main`. It creates a private temporary directory, fetches all three files before sourcing, and syntax-checks each, but has no immutable source identity or trusted digest. No dedicated direct-pipe fallback tamper/path/no-network regression suite was found in the reviewed tests. | OPEN. Use versioned immutable source and a trusted digest; fail closed when unavailable. Test tampering, stale metadata, no network, traversal/symlink paths, and scoped deletion. |
| SEC-03 | Medium | `lib/auth.sh`, `lib/password.sh`, and the installed prompt asset derive startup credentials with one salted SHA-256 pass. The code compares shell strings. This is a convenience gate, not an Android UID or same-process security boundary; `docs/next/architecture/SECURITY-ROADMAP.md` correctly says so. | OPEN. Design a versioned portable KDF record and successful-login-only rehash; test legacy, wrong/corrupt record, interruption, recovery, timing/cost bound, and no secret output before migration. |
| REL-01 | Medium | Read-only live-source parity reports 17 mismatches against current `main` and 12 against release tag `v2.0.1`, among 1,648 installed Ternux-owned paths. The tag-based comparison has 10 native module/resource differences and 2 unmapped Debian/Ubuntu `/usr/local/bin/ternux-app-center` files. `main` adds 5 differences: four guest package-manager launcher copies and the current-vs-tag `lib/update.sh` difference. | OPEN. Determine intended installed-source version and ownership for each path; reconcile only Ternux-owned files through a managed, reversible migration and rerun parity. Do not equate `main` source with a published v2.0.1 install. |
| REL-02 | Medium | Current exact-head source contains journaled update staging and rollback. `tests/update_transaction.sh` passes locally and covers failure/rollback, crash recovery, concurrency, and symlink cases. Add or retain interrupted-network, disk-full, and actual Termux migration/rollback evidence before a stable v3 gate. |
| SEC-04 | Medium | `lib/extension.sh` verifies a workload's sidecar and expected archive SHA-256 and uses a constrained extraction flow; optional-installer fixtures reject checksum mismatch and unapproved source. The focused suite now verifies rejection of correctly rehashed traversal, escaping-symlink, and absolute symlink targets containing spaces before installation. Review reproduced that the previous `tar -tv` parser used `$NF` and accepted `/tmp/escape target`; the local fix uses GNU tar C-quoted metadata and rejects ambiguous/escaped link targets. The fix is fixture-verified, not yet qualified against every real workload release archive. | Partially verified. The named extension archive path/symlink cases are covered by fixtures, including the whitespace-target parser regression, but real release archives, other installer/download paths, workload metadata consistency, bundled native artifact provenance, and other extraction edge cases remain open; do not generalize one path's checks to all downloads. |
| SEC-05 | Medium | Native manager socket and Control Center have explicit local boundaries: the manager socket checks peer UID and private permissions; the dashboard binds loopback, uses short-lived bearer access, Host/Origin checks, confirmation-bound actions, and durable jobs. Current local tests pass (7 manager, 21 dashboard). | Verified for the named test cases only. Manager remains a foreground/read-only service; a service supervisor and full dashboard are partial/planned, not supported capabilities. |
| SEC-06 | Informational boundary | Ternux runs under the Termux Android app UID. PRoot is not a kernel security boundary. Current v3 security and extension docs state this limitation. | Accurate documentation; keep it visible in user-facing security claims and extension review. |
| DEP-01 | Medium | `package-lock.json` has 307 package records. All 112 records absent from the installed ARM64 Termux tree are marked optional; the 195 installed lock paths have exact version matches. Two optional `@emnapi` records lack a license field, and 12 installed packages expose no license-like file despite declaring an SPDX license. npm documents `resolved` as source location and `integrity` as the artifact SRI digest ([npm lockfile fields](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/)). | Corrected locally. An isolated candidate lock passed `npm ci` under verified Node v22.23.5 ARM64 in Debian PRoot (210 audited, zero advisories); `tests/npm_lock_integrity.py` now enforces HTTPS npm registry sources and SHA-512 SRI for every package. All package versions and the dependency graph remain unchanged. Lifecycle scripts, publisher provenance, licenses and artifacts still need audit. Native Android Node/npm still cannot start. |

- Third-party package and workload artifacts, licenses/notices, architecture, ELF dependencies, and exact digest provenance. npm lock metadata is now populated for all 105 baseline gaps, verified against exact official registry versions and enforced by CI; isolated `npm ci` passed with zero advisories. Lifecycle scripts, publisher provenance, licenses and artifacts remain under review. - Manager/Control Center/API schema compatibility and all authorization/error paths.
- Android permissions, storage binds, camera/microphone lifecycle, and extension/workload permission separation.
- Credential migration design and tests; no KDF change has been made.
- Secret scanning, workflow `permissions:` and token scope, dependency freshness and lock/hash coverage.

No severe issue here is described as a confirmed compromise. Findings concern mutable trust inputs, weak local credential hashing, source drift, qualification gaps, and incomplete architecture implementation.
