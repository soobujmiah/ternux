## Security and maintainability findings

- The startup-password verifier uses a salted single SHA-256 pass. The feature is explicitly documented as a convenience gate, not a security boundary; the Termux app owner can access guest files and bypass shell startup checks. A slow-KDF migration needs compatibility and recovery design and belongs in the v3 security plan unless a critical exploit is established.
- When `uninstall.sh` is invoked as a direct pipe without a local checkout or installed CLI, its fallback downloads implementation files from mutable `main`, syntax-checks them, then runs the scoped uninstaller. This is a reproducibility/supply-chain weakness; no evidence in this audit shows it crosses the documented scoped deletion safeguards. Prefer the exact release archive for versioned recovery, and design immutable pinning for a future security improvement.
- GitHub Actions use version tags rather than full commit-SHA pins, and no ShellCheck job is configured. These are supply-chain and analysis improvements, but no compromise or critical defect was verified here.
- Large shell modules and a broad aggregate test runner increase maintenance cost. Their size alone is not a v2 release blocker; modularization and test partitioning remain v3 work.
- The website dependency audit recorded nine high-severity paths through Picomatch in the build tree; the prior review found no verified patched version and did not add an unverified override. Recheck the dependency advisory state before release publication and do not claim the build toolchain is risk-free.

No confirmed critical security vulnerability was established by the available source/device/CI evidence. The independent audit is absent, so this is not a claim that two audits found none.
