**Release:** v1.4.0<br>
**Tag:** `v1.4.0`<br>
**Tag commit:** `3e6c07e2afcb5f1e65ecd57af19b0382a948835a`<br>
**Release status:** published historical release; no attached binary assets.

This guide installs the source snapshot tagged `v1.4.0`. It does not use the
current `main` installer. The tag's source archive was downloaded from GitHub
and its installer reported `ternux installer v1.4.0` on 2026-11-18. Archive
SHA-256 observed during that check:

```text
e3428805d0b9ba8c5875ee93b84fe38ff3eb16e32de9416e9bf1c2445e863eb6  v1.4.0.tar.gz
```

GitHub does not attach this archive or checksum as a release asset. Treat the
checksum above as the observed codeload response digest, not as a publisher-
signed artifact. Confirm the tag commit shown above before relying on the
download.

## Requirements

- ARM64 Android device with adequate free storage (at least 5 GB recommended
  for the base installation, plus temporary download/cache space).
- Termux from F-Droid or the Termux GitHub releases. Install Termux add-ons
  from the same source.
- Termux:X11 installed from its official GitHub project and opened once.
- Internet access, `pkg`, `bash`, `tar`, and either `curl` or `wget`.
- Android permission to install the Termux:X11 APK. Storage permission is
  optional; v1.4.0's guest can work without shared-storage access.

The device must be ARM64. This release uses a Debian PRoot desktop; it does not
provide root access or a kernel container.

## Install the exact v1.4.0 source

Open Termux and run:

```bash
pkg update -y
pkg install -y bash ca-certificates coreutils curl grep tar wget
work="$(mktemp -d)" || exit 1
archive="$work/v1.4.0.tar.gz"
url="https://codeload.github.com/soobujmiah/ternux/tar.gz/refs/tags/v1.4.0"
if ! curl -fL "$url" -o "$archive"; then
  wget -O "$archive" "$url" || exit 1
fi
printf '%s  %s\n' 'e3428805d0b9ba8c5875ee93b84fe38ff3eb16e32de9416e9bf1c2445e863eb6' "$archive" | sha256sum -c - || exit 1
tar -tzf "$archive" > "$work/archive.list" || exit 1
if grep -qE '(^/|(^|/)\.\.(/|$))' "$work/archive.list"; then
  echo 'Unsafe path found in source archive' >&2
  exit 1
fi
tar -xzf "$archive" -C "$work" || exit 1
bash "$work/ternux-1.4.0/install.sh"
printf 'Keep this directory if you need to resume: %s\n' "$work"
```

Keep the Termux session open until the installer finishes. If it stops at a
required phase, rerun the installer from the same extracted `ternux-1.4.0`
directory to resume. Do not remove the guest to retry. When the installation
has completed and you no longer need the downloaded source, remove only the
temporary directory printed by `printf '%s\n' "$work"`; check the path before
deleting it.

The archive is pinned to a tag, not a branch. The included libraries are used
from that archive, so this procedure does not fetch library code from `main`.

## Verify the release version

Before installation, the tagged installer must print:

```text
ternux installer v1.4.0
```

After installation, open a new Termux shell and run:

```bash
ternux --version
ternux doctor --quick
```

The first command must report `1.4.0`. Start the desktop with `x` or the
launcher installed by the release, then inspect the selected graphics route
with `ternux verify` and `glxinfo -B` inside the guest. A detected renderer is
not a performance or broad-device qualification claim.

## Support boundary and limitations

v1.4.0 is a historical Debian-first release. Its release-time guide and source
do not qualify the later Debian/Ubuntu/Kali/Alpine profile matrix. Termux:X11,
Android GPU drivers, package repositories, and device power policies vary by
device. PRoot does not provide root privileges or systemd. Optional workloads
may need extra storage and are not part of the base verification.

The archived v1.4.0 release page has no binary assets. Installation therefore
uses the GitHub-generated source archive for the immutable tag and verifies the
observed archive digest above. If GitHub no longer serves that archive, do not
substitute `main` or a newer tag; restore the source archive from the exact
commit `3e6c07e2afcb5f1e65ecd57af19b0382a948835a`.

## Troubleshooting and recovery

- **`curl` cannot start:** the command falls back to `wget`; if both fail, fix
  Termux packages/network access and retry the same tag URL.
- **Checksum mismatch:** stop. Do not extract or run the archive. Re-download
  and confirm the tag still resolves to the recorded commit.
- **Insufficient storage or interrupted setup:** free space without deleting
  the Ternux guest, then rerun the v1.4.0 installer with `--resume` if offered
  by the install state, or rerun its normal command to continue.
- **Desktop does not appear:** open Termux:X11 once, return to Termux, run
  `source ~/.bashrc`, then start the installed `x` launcher. See the v1.4.0
  troubleshooting page in the tagged source archive.
- **Upgrade to a later release:** use that later release's own guide. Do not
  point the v1.4.0 installer at a moving branch.
