# Ternux website visual system

The Ternux site uses a living Matrix terminal language across English and Bengali home and documentation routes. `src/layouts/SiteLayout.astro` owns the shared header, compact mobile menu, footer, code copy buttons, ambient code field, code-filled title, and numeric readout behavior. `src/styles/site.css` owns the responsive visual system. The home pages share `WorkstationDiagram`, `ComputeBench`, and `RenderBench` components.

The homepage uses a typography-led signal chamber. On wide screens, the centered canvas-rendered `LINUX` word on the English home and `লিনাক্স` on the Bengali home keep a fine outline and depth trace while `TERNUX` glyphs fall inside the letter mask. On mobile, bundled Space and Noto Bengali render the stable letter shape, with a clipped canvas rain layer inside it; the DOM title stays readable as the rain moves and when animation is unavailable or reduced motion is requested. Beneath `LINUX`, the English tagline reads “Workstation In Your Pocket”; beneath `লিনাক্স`, the Bengali tagline reads “ওয়ার্কস্টেশন আপনার পকেটে”. English body copy uses the bundled Space font, while Bengali copy uses bundled Noto Bengali with Space for Latin characters. The ambient falling field repeats `TERNUX` in its animated canvas and static fallback. It is denser at the margins while a central mask keeps copy readable. The hero's Android → Termux → Debian → Adreno route carries a signal that travels left and right without jumping. The system map presents six open nodes, including the assembled Ternux workstation, with a soft signal passing between them; the workstation phone diagram follows it. On mobile the hero route and system nodes use two columns, both hero actions share one row, and the diagram caption has its own space below the art. The same restrained signal line appears on section and documentation headings. The phone diagram's labels are illustrative, so avoid invented battery, network, or performance readings. The charts and render timeline use exact preserved values with evidence labels. Numeric DOM text remains the source of truth. On entering the viewport, decorative glyphs briefly decode to that same value and then stop. Reduced motion, no JavaScript, and assistive technology receive the original static text.

Documentation pages use the same colors, typography, code atmosphere, header, and footer. Their background is quieter for reading. The documentation index uses open signal rows instead of dense cards. Wide Markdown tables scroll within the article at narrow widths. Reveal styling activates only after JavaScript starts, so all sections remain readable when scripts are unavailable. Keep long-form claims and evidence boundaries in the canonical Markdown docs; do not turn experimental HTP or untested paths into supported features through visual copy.

Both homepages follow the same six-part story: verified Android host, system map, first boot, ADT inside the guest, measured compute paths, and verified 3D output. The host profile shows host facts only; the system map introduces the guest and display. The render timeline uses a small animated wireframe mesh as a visual cue, while the measured numbers and caveats stay in text. On mobile all five render stages fit in a compact two-column layout.

The static build finalizes `.html` routes and sitemap output. Use the built output when reviewing `.html` documentation links locally; Astro's development server may return 404 for those finalized paths. Preserve canonical URLs, language alternates, structured data, and code copy behavior when changing the layout.
