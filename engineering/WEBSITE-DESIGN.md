# Ternux website visual system

The Ternux site uses a living Matrix terminal language across English and Bengali home and documentation routes. `src/layouts/SiteLayout.astro` owns the shared header, compact mobile menu, footer, code copy buttons, ambient code field, title particles, and numeric readout behavior. `src/styles/site.css` owns the responsive visual system. The home pages share `WorkstationDiagram`, `ComputeBench`, and `RenderBench` components.

The homepage now uses a typography-led signal chamber rather than the earlier perspective corridor and particle-diffusion treatment. The centered canvas-rendered `LINUX` word keeps a fine outline and depth trace while streams of hexadecimal glyphs move inside the letter mask. The word does not break apart. The DOM title stays as the readable fallback when animation is unavailable or reduced motion is requested. The English and Bengali taglines both say “Workstation … in your pocket” in the self-hosted Atma handwriting face (`assets/fonts/atma-regular.ttf`, SIL OFL 1.1 license alongside it). The hero's Android → Termux → Debian → Adreno route carries a moving signal; the workstation phone diagram lives with the system map. On mobile the route becomes two columns and both hero actions share one row. The same restrained signal line appears on section and documentation headings. The phone diagram's labels are illustrative, so avoid invented battery, network, or performance readings. The charts and render timeline use exact preserved values with evidence labels. Numeric DOM text remains the source of truth. On entering the viewport, decorative glyphs briefly decode to that same value and then stop. Reduced motion, no JavaScript, and assistive technology receive the original static text.

Documentation pages use the same colors, typography, code atmosphere, header, and footer. Their background is quieter for reading. The documentation index uses open signal rows instead of dense cards. Keep long-form claims and evidence boundaries in the canonical Markdown docs; do not turn experimental HTP or untested paths into supported features through visual copy.

The static build finalizes `.html` routes and sitemap output. Use the built output when reviewing `.html` documentation links locally; Astro's development server may return 404 for those finalized paths. Preserve canonical URLs, language alternates, structured data, and code copy behavior when changing the layout.
