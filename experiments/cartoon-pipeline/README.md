# Bulbul and the stubborn flower — a phone-rendered animated short

> **Where this sits in ternux.** This is a worked example of the `--with-blender`
> workload: a complete animated film produced on the phone, with the exact
> commands that produced it. It is kept here rather than in the installer
> because nothing in ternux depends on it — it is evidence that the workstation
> does real production work, and a starting point for doing it yourself. The
> measured render numbers are in [Evidence & benchmarks](../../docs/BENCHMARKS.md).

A complete 3D animated short produced on an Android phone: Redmi Turbo 4 Pro,
Termux with PRoot Debian 13, Blender 4.3.2 rendering on the Adreno 825 through
zink and Mesa Turnip. Four shots, 27 seconds, 648 frames at 1280×720, with a
synthesised soundtrack. Nothing is downloaded: every model is built from Blender
primitives by the scripts in this directory, and every sound is generated by
`audio.py` from the Python standard library.

## Requirements

- Blender 4.3.2 (Debian trixie package)
- `Xvfb` — `sudo apt install -y xvfb` (not part of any ternux workload yet)
- `ffmpeg` — `sudo apt install -y ffmpeg`; optional, since Blender's own FFMPEG writer can encode instead
- a working GPU path: zink over a Turnip new enough to enumerate the Adreno

## Produce the whole film

```sh
./render_all.sh                 # four shots, one Blender process each
python3 audio.py out/audio.wav  # the soundtrack
python3 assemble.py             # encode, concatenate, mux
```

The result is `out/bulbul-and-the-stubborn-flower.mp4`.

## The display rule

Blender's EEVEE needs an OpenGL context, but it does not need a visible one.

```sh
Xvfb :9 -screen 0 1280x720x24 &
DISPLAY=:9 GALLIUM_DRIVER=zink blender -b --factory-startup --python render.py -- --shot 1
```

`blender-headless.sh` does exactly this, starting `Xvfb` if it is not already
running. Both halves matter:

| What you run | What happens |
|---|---|
| `DISPLAY=:9 GALLIUM_DRIVER=zink blender …` | renders on the Adreno |
| `DISPLAY=:0 blender …` (Termux:X11 app open) | renders on the Adreno, same speed |
| `DISPLAY=:9 blender …` | `Illegal instruction`, zero frames — Mesa picked `llvmpipe` |
| `blender …` with no `DISPLAY` | `EGL_BAD_MATCH`, zero frames |

Measured over the same ten frames: 1.697 s/frame headless against 1.733 s/frame
on the real display, and the same frame rendered down both paths differs in 5
channel samples out of 2,764,800.

## Measured

The delivered cut, rendered headless on a Redmi Turbo 4 Pro (Adreno 825):

| Shot | Frames | Blender render time | Mean | Wall clock |
|---|---|---|---|---|
| 1 | 144 | 164.5 s | 1.142 s | 209 s |
| 2 | 144 | 160.3 s | 1.113 s | 205 s |
| 3 | 168 | 192.4 s | 1.145 s | 244 s |
| 4 | 192 | 212.4 s | 1.106 s | 270 s |
| **All** | **648** | **729.6 s** | **1.126 s** | **928 s** |

No slowdown across the run: the first 30 frames averaged 1.186 s and the last 30
averaged 1.149 s. Peak Blender memory 86.6 MiB. Thermal samples over the final
6.3 minutes: GPU zone 52.3–63.4 °C, `quiet_therm` 47.7–50.0 °C, battery 43.5 °C
rising to 44.5 °C. Roughly fifteen minutes of sustained load; this says nothing
about multi-hour behaviour.

The first frame of each shot cost 2.95–4.06 s against a 1.1 s steady state. That
is the shader compilation a sequence pays once per process, and the reason
`render_all.sh` renders a whole shot in one invocation.

## Working on one part

```sh
./blender-headless.sh -b --factory-startup --python render.py -- --shot 3 --still 44
./blender-headless.sh -b --factory-startup --python render.py -- --shot 2 --range 40:70
./blender-headless.sh -b --factory-startup --python render.py -- --shot 1 --save-blend
```

A still costs about four seconds including startup, which is the right loop for
checking a pose or a camera. Never render a sequence as one process per frame:
shader compilation is paid once per process and costs roughly twenty seconds.

## What each file does

| File | Role |
|---|---|
| `scene.py` | materials, lights, meadow, the hero flower, the character, and the keyframe helpers |
| `shots.py` | one function per shot: its camera and its animation, returning its length |
| `render.py` | the Blender entry point — `--shot`, `--still`, `--range`, `--save-blend` |
| `audio.py` | the soundtrack: music bed, ambience and spot effects, all synthesised |
| `assemble.py` | per-shot encode, concatenation, and the audio mux |
| `blender-headless.sh` | the display rule in one command |
| `render_all.sh` | all four shots, with per-shot frame counts and timings |

## How the character is put together

There is no armature. The character is a tree of parented empties:

```text
ctrl      where he is in the world
└ squash  squash and stretch, pivoting at his feet
  └ lean  whole-body tilt, pivoting at his middle
    ├ head_pivot   eyes, pupils, glints, beak, head tufts
    ├ arm_l_pivot  the left arm, so a rotation reads as a wave
    ├ arm_r_pivot  the right arm
    └ body, belly, feet
```

Every position in the project is written in world space, and `scene.attach()`
applies the parent inverse so that a child does not inherit its parent's offset
twice. That one rule is the difference between a character and a pile of spheres
floating above the ground.

## Reproducibility

- `--factory-startup` on every invocation, so no saved preference can change the
  output.
- The audio noise source is a seeded LCG, so `audio.py` produces the same WAV
  every time.
- `view_transform = "Standard"`: Blender's default AgX desaturates a cartoon
  palette into pastel.
- Raytracing is off. At 16 samples it contributes grain rather than detail to
  flat cartoon shading, and it costs about three times the frame time.
