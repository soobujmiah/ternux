### CLIP conditioning — the three things step 1 said to check

Read from the reference copies in `~/npu-probe-2026-10-13/localdream-reference/`.
This is reference reading, not code to carry over.

**Embedding arithmetic.** For each position `i` in `0..76`, with `dim = 768`:

```text
embeddings[i*dim + j] = fp16_to_fp32(token_emb[token_id*dim + j]) * weight
                        + pos_emb[i*dim + j]
```

`weight` is per-position and defaults to `1.0` (it exists for prompt
weighting). If a row is already non-zero — a pre-set custom embedding — then
only `pos_emb` is added to it, and the token lookup is skipped. `pos_emb` is
FP32 and is added to every row unconditionally.

**Token table format.** `force_fp16` is true only for SDXL and for the
encoder-2 table, so for SD1.5 the format is decided by **file size**: larger
than 100 MB is treated as FP32 on disk and narrowed to FP16 in memory; at or
below that it is FP16 on disk and mmapped with `MADV_RANDOM`. Either way the
in-memory table is FP16 and every lookup goes through `fp16_to_fp32`.

That last point matters for a known-answer comparison: an independent
implementation that keeps FP32 precision end to end will **not** be
bit-identical to this reference, because the reference narrows an FP32 table to
FP16 before use. Decide deliberately whether to match that narrowing or to
record the difference as expected.

**MNN CLIP IO.** CLIP runs as a persistent MNN session on CPU while UNet and VAE
run as persistent QNN/HTP contexts. The session input tensor is named
`input_embedding` and is resized to `{1, 77, text_embedding_size}`, which is 768
for SD1.5; the output is `last_hidden_state`. The interpreter is created mmapped.

**Not checked:** the tokenizer's exact special-token and padding behaviour. That
is still open and is the remaining part of step 1.
