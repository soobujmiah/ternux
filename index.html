STEP 1

Install two apps

Termux — the host terminal. From GitHub releases or F-Droid. Not the Play Store — that build is abandoned and its repositories are dead.
Termux:X11 — the app that displays the desktop. From GitHub releases. Open it once, then leave it.

STEP 2

Run the one-command installer

Open Termux and paste. The installer detects your GPU, installs the base packages, builds Debian + Xfce4, configures the graphics path, writes the launcher and verifies everything (11 phases).

$ curl -fsSL https://soobujmiah.github.io/ternux/install.sh | bash

Prefer to read a script before running it? Same installer, two extra commands:

$ curl -fsSL https://soobujmiah.github.io/ternux/install.sh -o install.sh $ less install.sh # skim it — one file, organised in phases $ bash install.sh

Interrupted? Run it again — every phase is idempotent, and --resume skips completed work.
Want to do every step by hand instead? → Manual installation

STEP 3

Start the desktop

$ source ~/.bashrc $ x

x launches: audio bridge → display → Debian → Xfce4. Switch to the Termux:X11 app — your desktop is there.

STEP 4

Prove the GPU is real

Inside the desktop, open a terminal (right-click → Open Terminal Here):

$ glxinfo | grep "renderer string"

✅ zink Vulkan (Adreno (TM) … (MESA_TURNIP)) or virgl = hardware GPU path.
❌ llvmpipe = software rendering — fix it, don't live with it.

NOTE

Android 12+ users

Android's "phantom process killer" silently kills background processes — the #1 cause of a desktop dying with no error. The installer detects it and prints the exact fix: on Android 14+ it's one Developer-Options toggle (Disable child process restrictions); on 12–13 it's one ADB command.

OPTIONS

Installer flags and workloads

$ bash install.sh --yes # defaults, no questions $ bash install.sh --with-llm --with-dev # local AI + dev tools $ bash install.sh --resume # continue an interrupted install

More: --user, --locale, --backend zink|virgl, --zsh, --with-network, --with-media, --with-blender, --all.

MANAGE

Ternux CLI — permanent management interface

After installation, use the ternux CLI for everything:

$ ternux doctor # system diagnostics $ ternux doctor --json # AI-readable structured output $ ternux start # start the desktop $ ternux stop # stop the desktop $ ternux repair # auto-fix common issues $ ternux verify # verify installation $ ternux backend set virgl # switch GPU backend $ ternux update # self-update ternux CLI $ ternux info --json # machine-readable system info $ ternux uninstall # component removal

Every command supports --help, --json, --verbose, and --quiet.

UNINSTALL

Clean removal

$ curl -fsSL https://soobujmiah.github.io/ternux/uninstall.sh | bash

Everything lives inside Termux — deleting Termux's data removes ternux completely. Android's files are never touched.

Step zero

Which graphics path is your phone on?

Qualcomm Adreno — the fast path

If ls /dev/kgsl-3d0 finds the device, you have an Adreno GPU. The installer picks Zink automatically: OpenGL → Vulkan → Turnip → hardware.

preferred supported routehardware accelerated

The trap: the Turnip package ships no Vulkan loader. Miss libvulkan1 and Zink silently falls back to CPU rendering — with no error message at all. The installer installs the loader, the ICD and the driver, then verifies all three.

Mali, Xclipse, PowerVR — the compatible path

No /dev/kgsl-3d0 means no Turnip. The installer selects VirGL, which pipes GL commands to a helper process on the Termux side. Slower, but it is the path that works.

compatibility over peak speedhardware-assisted

Note: nothing can make a Mali GPU take the Turnip path. Choosing VirGL correctly is the win here.

Design decisions

Why ternux works the way it does

Why no root?

Rooting voids warranties and exposes the whole device. PRoot fakes a root filesystem in userspace — the container believes it owns the system while Android's sandbox stays intact. Uninstalling ternux = deleting one folder.

Why Zink + Turnip?

Adreno phones have a Vulkan driver but no desktop OpenGL driver. Zink translates GL to Vulkan; Turnip drives the hardware. Together: real GPU acceleration for desktop apps — not CPU-bound llvmpipe.

Why verified phases?

A visible desktop is not proof of success — software rendering looks fine until you run Blender. Every phase checks its work before the next starts, so failures are loud, early and repairable (--resume, --doctor).

Why one auditable script?

The installer is a single MIT-licensed file you can read before running. No binaries, no hidden endpoints. Trust through transparency, convenience through one command.
