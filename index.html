Full installation guide

The same thing the one command does — written out step by step, so you can follow along right here.

STEP 1

Install two apps

Termux — the host terminal. Use the main release from GitHub or F-Droid, and keep every plugin from the same source. The Google Play line is separate and experimental.
Termux:X11 — the app that displays the desktop. From GitHub releases. Open it once, then leave it.

STEP 2

Run the one-command installer

Open Termux and paste. The installer detects your GPU, installs the base packages, builds Debian + Xfce4, configures the graphics path, writes the launcher and verifies everything (11 phases).

$ curl -fsSL https://soobujmiah.github.io/ternux/install.sh | bash

Prefer to review everything before running it? Clone the source so the entry script and every module it uses are local:

$ pkg install git -y $ git clone https://github.com/soobujmiah/ternux.git && cd ternux $ git log -1 --oneline $ (set -e; for f in install.sh uninstall.sh bin/ternux lib/*.sh; do bash -n "$f"; done) $ less install.sh bin/ternux lib/*.sh $ bash install.sh

Interrupted? Run with --resume; only phases recorded as successful are skipped. A local run asks once before changes, while the piped route is unattended.
Want to do every step by hand instead? → Manual installation

STEP 3

Start the desktop

$ source ~/.bashrc $ x

x launches: audio bridge → display → Debian → Xfce4. Switch to the Termux:X11 app — your desktop is there.

STEP 4

Prove the GPU is real

Inside the desktop, open a terminal (right-click → Open Terminal Here):

$ glxinfo | grep "renderer string"

✅ zink Vulkan (Adreno (TM) … (MESA_TURNIP)) confirms the captured direct Adreno path. virgl/virpipe confirms the fallback route is selected, but support and speed vary.
❌ llvmpipe = CPU software rendering — troubleshoot before benchmarking.

NOTE

Android 12+ users

Android 12+ may terminate PRoot child processes, while memory pressure and OEM battery policy can look similar. The installer reports readable settings and points to version-aware troubleshooting; review the system-wide trade-off before changing Android safeguards.

OPTIONS

Installer flags and workloads

$ bash install.sh --yes # defaults, no questions $ bash install.sh --with-llm --with-dev # local AI + dev tools $ bash install.sh --resume # continue an interrupted install

More: --user, --locale, --backend zink|virgl, --zsh, --with-network, --with-media, --with-blender, --all.

MANAGE

Ternux CLI — permanent management interface

After installation, use the ternux CLI for everything:

$ ternux doctor # system diagnostics $ ternux doctor --json # machine-readable structured output $ ternux start # start the desktop $ ternux stop # stop the desktop $ ternux repair # auto-fix common issues $ ternux verify # verify installation $ ternux backend set virgl # switch GPU backend $ ternux update # self-update ternux CLI $ ternux info --json # machine-readable system info $ ternux uninstall # component removal

Global flags are recognized by the dispatcher; JSON output is command-specific. See the CLI reference for supported schemas.

UNINSTALL

Clean removal

$ curl -fsSL https://soobujmiah.github.io/ternux/uninstall.sh | bash

The managed container, launcher and state live inside Termux; clearing app data removes them, but shared-storage projects and external backups remain. The scoped uninstaller does not delete files outside Termux.

Step zero

Which graphics path is your phone on?

Qualcomm Adreno — the direct path

If ls /dev/kgsl-3d0 finds the device, you have an Adreno GPU. The installer picks Zink automatically: OpenGL → Vulkan → Turnip → hardware when the driver supports that device; verify the renderer rather than assuming.

tested Adreno routeverify the renderer

The trap: the Turnip package ships no Vulkan loader. Miss libvulkan1 and Zink silently falls back to CPU rendering — with no error message at all. The installer installs the loader, the ICD and the driver, then verifies all three.

Mali, Xclipse, PowerVR — the compatible path

No /dev/kgsl-3d0 means no Turnip. The installer selects VirGL, which pipes GL commands to a helper process on the Termux side. Feature coverage, acceleration and speed vary by device, so verify the renderer and workload.

compatibility candidatedevice-dependent

Note: nothing can make a Mali GPU take the Turnip path. Choosing VirGL correctly is the win here.

Design decisions

Why ternux works the way it does

Why no root?

Root-based changes can affect verified boot and enlarge the blast radius. PRoot emulates a root-like filesystem without Android root, but it is not a security boundary: Termux-accessible paths remain reachable. Use the scoped uninstaller and back up the Debian container first.

Why Zink + Turnip?

On supported Adreno devices, Android exposes Vulkan/KGSL rather than a normal desktop OpenGL stack. Zink translates GL to Vulkan and Turnip drives the GPU; confirm the route with renderer evidence instead of assuming that a successful launch means acceleration.

Why verified phases?

A visible desktop is not proof of success — software rendering looks fine until you run Blender. Every phase checks its work before the next starts, so failures are loud and early. Resume continues interrupted installs; ternux repair applies supported targeted fixes.

Why auditable source?

The MIT-licensed bootstrap and library modules can be downloaded and reviewed before execution. The documentation identifies the GitHub, Termux/Debian and Mesa sources used for code, packages and driver assets; the one-command route trades some reviewability for convenience.
