01What is Ternux?

Ternux composes a userspace Linux environment around Android services — it never replaces Android. Every layer is explicit and reviewable.

LayerComponentPurpose
Android appTermux:X11Displays the Linux X11 desktop on Android
Termux hosttermux-x11, PulseAudio, PRoot DistroDisplay socket, Android audio, container lifecycle

Fallback graphicsVirGLPortable virtual OpenGL route for other devices

01No root, no bootloader change

PRoot userspace only. The Android system partition is never modified; guest root inside PRoot is not a security boundary.

02Explicit graphics routes

Zink/Turnip where the Adreno driver path is supported; VirGL as the public compatibility route. A working desktop alone is never presented as proof of hardware rendering.

03Auditable everything

Plain Bash you can read before running: clone-first review path, syntax checks, and a full installer log in ternux.log.

04Real applications

Xfce Terminal, VLC, Mesa and Vulkan utilities included; development tools, llama.cpp, media tools and Blender opt-in.

04GPU acceleration

Two explicit routes. Which one you get depends on your GPU — ternux detects, reports, and never hides the choice.

Adreno route — Zink over Turnip

On supported Adreno devices, OpenGL is translated to Vulkan and sent straight to the Qualcomm driver (KGSL). This is the measured path: glmark2 OpenGL 4.6 compatibility profile, OpenGL ES 3.2, and the same renderer string observed in Blender's viewport.

zink Vulkan 1.4(Adreno (TM) 825 (MESA_TURNIP))
Measured

VirGL route — the compatibility fallback

For devices without the Adreno path, VirGL provides a portable virtual OpenGL route. A working desktop on VirGL is reported as exactly that — never as hardware acceleration.

05Evidence — measured, never blended

The published snapshot comes from one Redmi Turbo 4 Pro (Snapdragon 8s Gen 4 / Adreno 825, August 2026). It shows this route worked there; it does not promise the same result on every phone.

glmark2 — OpenGL

140 score · 800×600 windowed · 45–164 FPS across 33 scenes. A suite aggregate, not constant desktop FPS.

06Ternux and ADT — two layers of one ARM64 story

Android Device │ ┌────────────┴────────────┐ │ │ ADT Ternux │ │ Android development Linux ARM64 desktop Build / Sign / ADB Debian / Xfce4 / GPU

Ternux — this project

The Linux desktop layer: no-root Debian + Xfce4 on Android via PRoot and Termux:X11, with measured GPU acceleration on supported Adreno devices.

ADT — the toolchain layer

Native ARM64 Android SDK build-tools, platform-tools, signing and ADB workflows — built from AOSP source for Linux ARM64, verified end-to-end on a real device. If you develop Android apps on this kind of hardware, ADT is the companion project.

ADT website →

Host-device workflow

Development and execution occur on the same physical Android hardware: Ternux builds the artifact in Debian userspace, while ADT installs and debugs it directly on the host device via ADB without external emulators.

Verified vs experimental

Both projects are verified separately on the same Termux + PRoot Debian foundation (Redmi Turbo 4 Pro). Cross-project workflows and closed-loop agent automation coexist architecturally but remain experimental until formally measured.
